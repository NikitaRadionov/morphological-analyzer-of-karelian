# Морфологический анализатор карельского языка

Анализатор словоформ для письменного карельского (Karelian Proper, New Written
Karelian standard). По введённой словоформе определяет лемму и набор
грамматических тегов (часть речи, падеж, число, время, лицо и т.д.).

Основа проекта — конечный преобразователь (FST), построенный по схеме курса
(`lexd` для лексики/парадигм + `hfst-twolc` для двухуровневых правил
морфофонологии), а не просто поиск по словарю. FST реально моделирует
карельскую консонантную градацию и глагольное чередование суффиксов и
генерализует на формы, которых не было в обучающих данных — в отличие от
табличного словаря, который покрывает только то, что в нём явно записано.

## Данные

Используется датасет [UniMorph/krl](https://github.com/unimorph/krl)
(файл `krl-new-written-karelian`): 253 259 пар лемма–словоформа, 2 836 лемм,
242 452 уникальных словоформ. Данные собраны на основе словаря карельского
языка и распространяются под лицензиями CC BY-SA / CC BY.

## Как это работает

Анализ словоформы идёт по трём уровням, от точного к приблизительному:

1. **FST (lexd+twol)** — настоящий морфологический анализ через двухуровневый
   преобразователь. Покрывает 5 классов именной градации (без чередования;
   геминация `kk~k`, например *akka~akan*; леницию `p~v`, например
   *arpa~arvan*; полное выпадение `k~∅` с гласными `u`/`a`, например
   *alku~alun*, *huahka~huahan*) и 4 класса глагольного спряжения
   (инфинитив vs наст. время 3 л. ед. ч.: `ua~au`, `o~u`, `yä~äy`, `ö~y`).
   Правила выведены эмпирически — сравнением NOM.SG/GEN.SG и NFIN/PRS.3SG
   по всем леммам датасета, а не взяты из учебника. На покрытых классах
   точность генерации/анализа — 100% (476/476 проверенных форм), включая
   формы, которых не было ни в одном обучающем сплите.
2. **Словарь (lookup)** — точный поиск по таблице известных пар
   лемма–словоформа: мгновенно, 100% точность, но 0% обобщения на новые
   слова.
3. **Суффиксная эвристика** — для слов, не покрытых ни FST, ни словарём:
   ищет самый длинный суффикс, встречавшийся в обучающих данных, и
   предсказывает лемму/теги по аналогии.

В вебе результат каждого анализа помечен источником (`FST-анализ` /
`в словаре` / `предсказано`).

## Запуск

```bash
python data/download.py        # один раз — скачать данные
python app/app.py               # запустить веб-интерфейс → http://localhost:5000
python evaluation/eval.py       # оценить качество анализатора
```

Пересборка FST (нужен WSL с `hfst`/`lexd`, см. ниже):

```bash
python fst/generate_lexd.py                          # данные → karelian.lexd
wsl -d Ubuntu -- bash -c "cd fst && bash build.sh"    # компиляция в WSL
python fst/validate.py                                # проверка против UniMorph
```

Установка тулчейна в WSL Ubuntu (однократно):

```bash
curl -s https://apertium.projectjj.com/apt/install-nightly.sh | sudo bash
sudo apt-get install -y hfst lexd cg3
```

## Результаты оценки

| Метрика                                                     | Значение |
|--------------------------------------------------------------|----------|
| FST: точность на покрытых классах градации/спряжения         | 100% (476/476) |
| FST: лемм охвачено демо-выборкой классов                      | 238      |
| Словарь: точность на известных формах                         | 100%     |
| Эвристика: точность тегов на полностью новых леммах            | ~55%     |
| Эвристика: точное совпадение на полностью новых леммах          | ~4%      |
| Лемм в полном датасете                                          | 2 836    |
| Словоформ в полном датасете                                      | 242 452  |

FST и словарь/эвристика покрывают разные срезы данных и не сравниваются на
одном тестовом наборе: FST по построению генерализует на любые формы внутри
смоделированных классов (включая невиданные леммы), словарь — только на то,
что в нём явно записано, а эвристика — единственный механизм, работающий
на леммах за пределами словаря и FST.

## Ограничения

- FST покрывает лишь часть продуктивных классов градации/спряжения и
  ограниченную (демо) выборку лемм на класс — это демонстрация подхода
  курса, а не полный анализатор всех 2 836 лемм. Расширение до полного
  покрытия — это в первую очередь работа по классификации данных
  (`fst/generate_lexd.py`), сама инфраструктура (lexd+twol+сборка) уже
  готова к этому.
- `hfst`/`lexd` не имеют сборки под Windows — компиляция и вызов
  `hfst-optimized-lookup` идут через WSL (`fst/fst_analyzer.py` вызывает
  `wsl.exe` из Python).
- Анализатор не учитывает контекст (омонимичные формы выдаются все сразу);
  стадия Constraint Grammar для дизамбигуации не реализована.
- Покрывает только письменный стандарт New Written Karelian; диалектные
  формы (вокнаволокский, кестеньгский и др.) не включены.
